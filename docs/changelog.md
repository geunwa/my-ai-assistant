# 변경 기록

큰 수정이 있을 때마다 아래에 이어서 적는다. 항목마다 발견한 문제, 바꾼 것, 근거, 수정 전후 증빙 파일명을 남긴다.

## STEP 10-2: 서비스명 떠날까 적용, 디자인 개선, 지수 단위와 출처 표기

### 발견한 문제
1. 요약 카드의 숫자(평균 39.7, 최대 100 등)에 단위와 기준이 없어 "검색 횟수"로 오해하기 쉬웠다.
2. 데이터의 출처와 수집 조건이 화면 어디에도 없었다.
3. 날짜가 무엇을 뜻하는지(그 주의 시작일) 설명이 없었다.
4. AI 답변이 "최근값: 77.0"처럼 숫자만 나열하고, 지수의 뜻이나 단위를 설명하지 않았다.
5. 서비스 이름과 분위기가 없는 기본 화면이었다.
6. 표 열 이름과 입력칸 이름(날짜, 관심도)이 데이터의 실제 의미(주 시작일, 관심도 지수)와 달랐다.

### 바꾼 것
- 이름과 로고: 서비스명 "떠날까", 부제 "해외여행 검색 관심도 AI 비서", 탭 제목과 파비콘에 로고(frontend/assets/logo.svg) 적용.
- 디자인: 파스텔 하늘색 중심 색, 둥근 카드·버튼·알약 탭, 제목과 탭에 웹 폰트(Jua), 헤더의 구름과 점선 비행길, 채팅 로딩 때 점선 위를 오가는 비행기, 그래프 최고점의 비행기 표시. 이모지 없이 모두 SVG.
- 말투: 안내·오류·알림 문구를 부드러운 해요체로 통일(서버가 보내는 detail 문구는 그대로 표시).
- 단위와 설명:
  - 요약 제목 아래에 "주간 검색 관심도 지수 · 기간 중 검색이 가장 많았던 주 = 100 (검색 횟수 아님)".
  - 평균·최대·최소·최근값에 "/ 100" 기준 표기, 최근값에 "평균의 약 1.9배"(최근값 ÷ 평균을 화면에서 계산).
  - 데이터 수 "261주 (약 5년)", 기간 아래 "날짜 = 그 주의 시작일(일요일)".
  - 추세는 서버 요약 값(60.0, 35.2, 70.2%)을 그대로 써서 한 문장으로 표시.
  - 그래프 세로축 제목 "관심도 지수", 가로축 처음과 끝 날짜.
  - 데이터 관리 표와 입력칸 이름을 "주 시작일", "관심도 지수 (0~100)", "메모"로 변경.
  - 출처 줄 추가.
- AI 답변(backend/app/services/chat_service.py): 시스템 프롬프트에 출처, 지수의 뜻, "날짜는 주 시작일", 숫자에 "관심도 지수 77(최고 100 기준)" 형식으로 단위를 붙이는 규칙, 친절하고 짧은 해요체, 요약에 없는 값은 지어내지 않는 규칙을 넣었다. 대화의 첫 답변에서만 "검색 횟수가 아니라 상대 지수"임을 짚고, 이어지는 답변에서는 반복하지 않는다.
- 안정성: OpenAI 라이브러리를 불러오지 못하는 환경에서도 500 대신 안내 메시지(503)를 돌려주도록 처리를 추가했다.

### 근거(출처 정보)
- 데이터 출처: Google Trends, 검색어 "해외여행", 대한민국, 웹 검색, 수집일 2026-11-09 (사용자가 제공한 수집 조건).
- 값의 의미: 주간 검색 관심도 지수 0~100이며, 기간 중 검색이 가장 많았던 주가 100이다. 실제 검색 횟수나 출국자 수가 아니다(사용자가 제공한 데이터 설명).
- 날짜가 주 시작일(일요일)이라는 점은 데이터로 확인했다. 첫 날짜 2021-11-07과 마지막 날짜 2026-11-01이 모두 일요일이다.
- "약 5년"은 261주 ÷ 52 = 5.02로 계산했다.
- 최고점 100은 2026-10-18 주이며, 서버 요약 API(GET /api/data/summary)의 값이다.

### 함께 발견한 환경 문제
- 이 PC에서 Windows 애플리케이션 제어 정책이 OpenAI 라이브러리가 쓰는 서명되지 않은 파일(jiter.pyd)을 차단해, 로컬 서버(8000)의 채팅이 실패한다. 이전 STEP에서는 동작했으므로 PC의 보안 정책이 바뀐 것으로 보인다. 배포 서버(Render, Linux)에는 영향이 없다.
- 오류 원인(2026-11-19 재현): backend\.venv\Lib\site-packages\jiter\jiter.cp313-win_amd64.pyd 를 불러올 때 "ImportError: DLL load failed while importing jiter: 애플리케이션 제어 정책에서 이 파일을 차단했습니다." 가 난다(서명 상태 NotSigned). 고치지 않고 원인만 기록했고, 이후 채팅 확인은 배포 서버(config.js를 Render 주소로 둠)로 한다.
- 보안 설정은 변경하지 않았다. 새 프롬프트의 채팅은 차단된 파일을 사용하지 않는 시험 스크립트(저장소 밖)로 1회 확인했다.

### 추가 수정: 굵은 글씨 표시
- 배포 서버 채팅에서 답변의 마크다운 **굵게** 기호가 그대로 보였다. 말풍선(채팅·대화 기록 미리보기)에서 **텍스트**를 <strong>으로 표시하도록 고쳤다(innerHTML 없이 텍스트 노드와 strong 요소로만 구성). 시스템 프롬프트에는 굵게와 "- " 목록 외의 마크다운(제목, 표, 코드 블록)을 쓰지 않는 규칙을 추가했다.

### 알려진 한계
- 서버의 입력 검증 문구는 영어로 표시된다(예: "Input should be less than or equal to 100"). detail 문구를 그대로 보여 주는 요구사항 때문이며, 한국어로 바꾸려면 백엔드 메시지를 수정해야 한다.
- 요약만 프롬프트에 들어가므로 "특정 주의 값", 주별·월별 값 같은 질문에는 모른다고 답한다. STEP 13 보너스(Function Calling) 후보: 질문에 따라 데이터를 조회하는 함수를 모델이 호출하게 하면 해결할 수 있다.
