# 용어사전 (누적)

발표 자료용. 형식: 한글(영문, 읽는 법) - 쉬운 설명. STEP마다 계속 추가한다.

## STEP 1~4

- 가상환경(Virtual Environment, 버추얼 인바이런먼트) - 프로젝트마다 따로 쓰는 파이썬 설치 공간. 다른 프로젝트와 패키지 버전이 섞이지 않는다.
- pip(핍) - 파이썬 패키지를 설치하는 도구.
- requirements.txt(리콰이어먼츠) - 프로젝트에 필요한 패키지 목록 파일. 이 파일로 같은 환경을 다시 만든다.
- .gitignore(깃 이그노어) - Git이 추적하지 않을 파일 목록. 키 파일과 .env를 여기에 넣어 올라가지 않게 한다.
- clone(클론) - 원격 저장소를 내 컴퓨터로 통째로 복사하는 것.
- 시계열(Time Series, 타임 시리즈) - 시간 순서대로 기록된 데이터. 이 프로젝트의 주간 검색 관심도가 해당한다.
- 시드(Seed, 시드) - 처음에 채워 넣는 초기 데이터. seed.csv 261건.
- 요약 정보(Summary, 서머리) - 데이터 전체를 대표하는 숫자(개수, 기간, 평균, 최대 등)를 짧게 뽑은 것.
- 추세(Trend, 트렌드) - 시간이 지나면서 값이 오르는지 내리는지 나타내는 방향. 예: 상승 +70.2%.
- FastAPI(패스트에이피아이) - 파이썬으로 API 서버를 만드는 프레임워크.
- uvicorn(유비콘) - FastAPI 앱을 실제로 실행하는 서버 프로그램.
- 엔드포인트(Endpoint, 엔드포인트) - API의 개별 주소. 예: /api/data.
- 라우터(Router, 라우터) - 엔드포인트를 주제별로 묶어 관리하는 단위.
- 미들웨어(Middleware, 미들웨어) - 요청과 응답 사이에서 공통 처리를 하는 중간 계층.
- CORS(코스, Cross-Origin Resource Sharing) - 다른 주소의 웹페이지가 내 API를 호출해도 되는지 정하는 브라우저 보안 규칙.
- Swagger UI(스웨거 유아이) - API를 목록으로 보여주고 브라우저에서 바로 시험해 볼 수 있는 자동 문서 화면.
- Firebase(파이어베이스) - 구글의 백엔드 서비스 모음.
- Firestore(파이어스토어) - Firebase의 문서형 데이터베이스.
- 컬렉션(Collection, 컬렉션) - Firestore에서 문서들을 담는 폴더 같은 단위. 이 프로젝트의 data 컬렉션.
- 문서(Document, 도큐먼트) - 컬렉션 안의 데이터 한 건. 필드와 값으로 이루어진다.
- 서비스 계정(Service Account, 서비스 어카운트) - 사람이 아닌 서버 프로그램이 Firebase에 접속할 때 쓰는 전용 계정.
- 비공개 키(Private Key, 프라이빗 키) - 서비스 계정의 신분증 역할을 하는 파일. 유출되면 누구나 DB에 접근할 수 있어 절대 공개하지 않는다.
- 프로덕션 모드(Production Mode, 프로덕션 모드) - Firestore의 보안 규칙이 엄격한 상태. 서버(Admin SDK)만 접근하게 한다.
- Admin SDK(어드민 에스디케이) - 서버가 Firebase를 관리자 권한으로 다루는 개발 도구 모음.
- 초기화(Initialization, 이니셜라이제이션) - 프로그램이 Firebase를 쓰기 전에 키로 연결을 준비하는 과정.
- 클라이언트(Client, 클라이언트) - 서비스에 요청을 보내는 쪽. 여기서는 코드 안의 Firestore 연결 객체.
- 스모크 테스트(Smoke Test, 스모크 테스트) - 핵심 기능이 최소한 작동하는지 빠르게 확인하는 시험. check_firestore.py.

## STEP 5

- CRUD(크루드) - 만들기(Create), 읽기(Read), 수정(Update), 삭제(Delete). 데이터 관리의 네 가지 기본 동작.
- Pydantic(파이댄틱) - 입력 데이터의 형태를 검사하고 변환하는 파이썬 라이브러리. FastAPI가 내부에서 사용한다.
- 스키마(Schema, 스키마) - 데이터가 어떤 필드와 형식을 가져야 하는지 정한 설계도. schemas.py.
- 검증(Validation, 밸리데이션) - 들어온 값이 규칙에 맞는지 확인하는 것. 날짜 "abc"를 422로 거절하는 것이 예.
- HTTP 메서드(HTTP Method, 메서드) - 요청의 의도를 나타내는 동사. POST(생성), GET(조회), PUT(수정), DELETE(삭제).
- 상태 코드(Status Code, 스테이터스 코드) - 요청 결과를 숫자로 알려주는 응답. 200 성공, 201 생성됨, 404 없음, 422 입력 오류.
- 서비스 계층(Service Layer, 서비스 레이어) - API 주소 처리(라우터)와 DB 작업 로직을 나누는 중간 계층. data_service.py.
- 환경 변수 파일 경로(Env File Path) - .env를 어느 위치에서 읽을지 코드에 직접 지정하는 것. 실행 위치가 달라져도 같은 파일을 읽는다.

## STEP 6

- 적재(Load, 로드) - 파일의 데이터를 데이터베이스에 넣는 작업. seed.csv 261건을 Firestore에 넣었다.
- 배치(Batch, 배치) - 여러 쓰기를 묶어 한 번에 처리하는 방식. 한 번에 최대 500건이라 400건씩 나눠 보냈다.
- 중복 방지(Deduplication, 디듀플리케이션) - 같은 데이터가 두 번 들어가지 않게 막는 것. 컬렉션에 데이터가 있으면 멈추고 묻는다.
- dry-run(드라이 런) - 실제로 쓰지 않고 검사만 해 보는 예행 실행 옵션.
- BOM(Byte Order Mark, 비오엠) - 파일 맨 앞에 붙는 보이지 않는 표식. 그대로 읽으면 첫 열 이름이 깨져 utf-8-sig로 제거한다.

## STEP 7

- 대화 기록(Conversation History, 컨버세이션 히스토리) - 사용자와 AI가 주고받은 메시지의 저장본.
- 메시지 역할(Role, 롤) - 메시지를 쓴 쪽을 구분하는 값. user는 사용자, assistant는 AI.
- ISO 8601(아이에스오 에이티식스티원) - 날짜와 시각을 "2026-11-17T17:26:20+00:00"처럼 쓰는 국제 표준 표기.
- UTC(유티씨, 협정 세계시) - 시간대 차이가 없는 기준 시각. 한국은 UTC+9다.
- 목록 조회와 상세 조회(List and Detail) - 여러 건을 요약으로 보는 요청과, 한 건을 전체로 보는 요청.

## STEP 8

- 시스템 프롬프트(System Prompt, 시스템 프롬프트) - AI에게 역할과 참고 정보를 미리 알려 주는 숨은 지시문. 여기에 데이터 요약을 넣는다.
- 토큰(Token, 토큰) - AI가 글자를 세는 단위. 한국어는 대략 한 글자가 1~2토큰이다.
- max_tokens(맥스 토큰즈) - 답변 길이 상한. 비용과 응답 시간을 제한한다.
- OpenAI GPT(오픈에이아이 지피티) - 질문에 문장으로 답하는 대화형 AI 모델.
- API 키(API Key, 에이피아이 키) - OpenAI 사용 권한을 증명하는 비밀 문자열. 사용량만큼 과금된다.
- 호출 한도·속도 제한(Rate Limit, 레이트 리밋) - 짧은 시간에 보낼 수 있는 요청 수와 사용 한도.
- 타임아웃(Timeout, 타임아웃) - 응답이 오지 않을 때 기다리는 최대 시간.
- 가짜 객체(Mock, 목) - 외부 서비스 대신 흉내 내는 시험용 객체.
- finish_reason(피니시 리즌) - AI가 왜 답변을 멈췄는지 알려 주는 값. stop은 정상 종료, length는 토큰 한도에 걸려 잘림.
- 추론 토큰(Reasoning Token, 리즈닝 토큰) - 추론형 모델이 답을 만들기 전에 속으로 쓰는 토큰. 화면에 안 보이지만 한도와 비용에 포함된다.
- 추론형 모델(Reasoning Model, 리즈닝 모델) - 답하기 전에 먼저 생각하는 단계를 거치는 AI 모델.
- 베이스 URL(Base URL, 베이스 유알엘) - API 요청을 보내는 기본 주소. 바꾸면 다른 서버로 요청이 간다.

## STEP 9

- 배포(Deploy, 디플로이) - 내 PC에서만 돌던 프로그램을 인터넷의 서버에 올려 누구나 접속하게 하는 것.
- Render(렌더) - 코드를 올리면 서버로 실행해 주는 클라우드 호스팅 서비스. 이 프로젝트의 API 주소는 https://my-ai-assistant-pjlv.onrender.com 이다.
- 버전 고정(Pinning, 피닝) - 패키지 버전을 ==로 못 박아 어디서 설치해도 같은 결과가 나오게 하는 것.
- 루트 디렉터리(Root Directory, 루트 디렉터리) - Render가 빌드와 실행의 기준으로 삼는 폴더. 여기서는 backend.
- 빌드 명령·시작 명령(Build Command, Start Command) - 설치 단계에서 실행할 명령과 서버를 켤 때 실행할 명령.
- 0.0.0.0(제로 제로 제로 제로) - 이 서버로 들어오는 모든 네트워크 요청을 받겠다는 주소. 외부 접속에 필요하다.
- $PORT(포트 환경 변수) - Render가 정해서 알려 주는 포트 번호. 코드에 숫자를 직접 쓰지 않는다.
- 콜드 스타트(Cold Start, 콜드 스타트) - 한동안 잠들어 있던 서버가 첫 요청에 깨어나느라 응답이 느린 현상.
- 헬스 체크(Health Check, 헬스 체크) - 서버가 살아 있는지 주기적으로 확인하는 주소. /api/health.

## STEP 10

- 프론트엔드(Frontend, 프런트엔드) - 사용자가 눈으로 보고 누르는 화면 쪽 프로그램. HTML, CSS, JS로 만든다.
- HTML/CSS/JavaScript(에이치티엠엘, 씨에스에스, 자바스크립트) - 화면의 구조, 모양, 동작을 각각 맡는 웹의 기본 언어.
- fetch(페치) - 브라우저에서 서버 API를 호출하는 자바스크립트 기능.
- DOM(돔, Document Object Model) - 브라우저가 화면을 코드로 다루기 위해 만드는 요소의 나무 구조.
- XSS(엑스에스에스, Cross-Site Scripting) - 입력에 악성 스크립트를 심어 화면에서 실행시키는 공격. textContent로 넣어 막는다.
- 헤드리스 브라우저(Headless Browser, 헤드리스 브라우저) - 화면 창 없이 명령으로 실행해 페이지를 시험하는 브라우저.
- 로딩 표시(Loading Indicator, 로딩 인디케이터) - 처리 중임을 알리는 화면 표시.
- 페이지네이션(Pagination, 페이지네이션) - 긴 목록을 페이지로 나눠 보여 주는 방식.

## STEP 10-2

- 파비콘(Favicon, 파비콘) - 브라우저 탭 제목 옆에 보이는 작은 아이콘. 여기서는 로고를 쓴다.
- SVG(Scalable Vector Graphics, 에스브이지) - 확대해도 깨지지 않는 점·선·도형 기반 그림 형식. 로고, 구름, 비행기를 모두 SVG로 그렸다.
- 웹 폰트(Web Font, 웹 폰트) - 사용자의 PC에 없어도 인터넷에서 내려받아 쓰는 글꼴. 제목과 탭에 Google Fonts의 Jua를 썼다.
- 상대 지수(Relative Index, 릴러티브 인덱스) - 실제 개수가 아니라 기준 값과 비교해 0~100으로 나타낸 수. 검색이 가장 많았던 주를 100으로 둔다.
- 관심도 지수(Interest Index, 인터레스트 인덱스) - Google Trends가 검색 관심도를 0~100으로 나타낸 값. 검색 횟수가 아니다.
- Google Trends(구글 트렌드) - 검색어가 시간에 따라 얼마나 검색됐는지 상대적으로 보여 주는 구글 서비스. 이 프로젝트의 데이터 출처.
- CSS 애니메이션(CSS Animation, 씨에스에스 애니메이션) - 자바스크립트 없이 CSS만으로 움직임을 주는 기능. 로딩 비행기에 썼다.
- 변경 기록(Changelog, 체인지로그) - 무엇을 왜 어떻게 바꿨는지 날짜순으로 남기는 문서. docs/changelog.md.
- 애플리케이션 제어 정책(Application Control Policy, 애플리케이션 컨트롤 폴리시) - 신뢰하지 않는 프로그램 파일의 실행을 Windows가 막는 보안 기능.
- 네이티브 확장 모듈(Native Extension, 네이티브 익스텐션) - 파이썬 대신 C 등으로 만들어 속도를 높인 파일(.pyd, DLL). 서명이 없으면 보안 정책에 차단될 수 있다.

## STEP 11

- Vercel(버셀) - HTML·CSS·JS 같은 웹 화면을 인터넷에 올려 주는 배포 서비스. 프론트엔드를 tteonalkka.vercel.app에 올렸다.
- 정적 사이트(Static Site, 스태틱 사이트) - 서버에서 계산하지 않고 미리 만든 파일을 그대로 보내는 웹사이트. 이 프로젝트의 frontend 폴더가 해당한다.
- 루트 디렉터리(Root Directory, 루트 디렉터리) - 배포 서비스가 저장소 안에서 기준으로 삼는 폴더. Vercel은 frontend로 지정했다.
- 오리진(Origin, 오리진) - 웹 주소에서 프로토콜·도메인·포트를 합친 부분. CORS 허용 목록(ALLOWED_ORIGINS)에 적는 단위다.

## STEP 12

- README(리드미) - 저장소 첫 화면에 보이는 설명 문서. 소개, 실행 방법, 배포 주소 등을 적는다.
- 마크다운(Markdown, 마크다운) - #, -, | 같은 기호로 제목·목록·표를 쓰는 간단한 문서 형식. README.md가 이 형식이다.

## STEP 13 (보너스)

- 내보내기(Export, 익스포트) - 화면 속 데이터를 파일로 저장하는 기능. 데이터 관리 탭에 CSV·JSON 내려받기 버튼을 넣었다.
- CSV(Comma-Separated Values, 씨에스브이) - 쉼표로 칸을 나눈 표 형식 텍스트 파일. 엑셀에서 바로 열린다.
- JSON(JavaScript Object Notation, 제이슨) - 이름과 값을 중괄호·대괄호로 묶어 적는 데이터 형식. API가 주고받는 형식과 같다.
- Blob(Binary Large Object, 블롭) - 브라우저에서 파일 내용을 담아 두는 덩어리. 서버 없이 화면에서 바로 파일을 만들어 내려받을 때 쓴다.

## STEP 14

- 빌드(Build, 빌드) - 배포 전에 파일을 복사·생성해 내보낼 결과물을 만드는 과정. Vercel이 배포 때마다 build.sh를 실행한다.
- 빌드 시점 주입(Build-time Injection, 빌드 타임 인젝션) - 실행 중이 아니라 빌드할 때 환경 변수 값을 파일에 써 넣는 방식. 정적 사이트는 브라우저가 환경 변수를 직접 읽지 못해서 이 방식을 쓴다.
- vercel.json(버셀 제이슨) - Vercel 배포 설정 파일. 빌드 명령과 배포 폴더를 적는다.
- 요구사항 추적표(Requirements Traceability Matrix, 리콰이어먼츠 트레이서빌리티 매트릭스) - 요구사항마다 구현 위치와 증빙을 짝지어 빠진 것을 찾는 표. docs/requirements-check.md.
